# SFT 效果的量化拆解（事后探索性）

本目录只读取已完成的 640 份结果，未启动训练、服务或模型调用，未修改原确认协议及封存结果。新计算均为**事后探索性诊断**。原主终点及其 50,000 次 bootstrap 区间以 `outputs/analysis.json` 为准；这里没有重新定义成功标准，也没有用子集结果替代原主终点。

## 可以支持的结论

完成率改善和完成后的地图质量改善同时存在。端到端 base/full128/new 的完成数为 95/123/128（分母均 128），原协议计零后的 F1 为 0.1771/0.5546/0.7248。base 的 33 次失败包含 21 次截断或缺 finish、12 次耗尽读出预算；full128 的 5 次失败均为截断或缺 finish；new 没有最终失败。

为避免只比较各自完成样本，将模型放在**同一批共同完成的父世界**上：

- base 与 new 共同完成 95 世界，F1 为 0.2386→0.7198，配对差 +0.4812，新增描述性 95% 区间 [0.4242, 0.5363]。
- full128 与 new 共同完成 123 世界，F1 为 0.5771→0.7245，配对差 +0.1474，区间 [0.1065, 0.1878]。
- 固定观察 reader 的 base 与 new 共同完成 101 世界，F1 为 0.2661→0.6602，配对差 +0.3941，区间 [0.3278, 0.4578]。

因此，“收益只来自更容易交出一个合法最终答案”与这些结果不符。不过，共同完成集合按模型运行后的状态筛选，仍是有选择的子集；上述数字不能解释成因果效应、机制占比，也不能从总收益中直接扣除。

## 精度、召回与定位

全部 128 世界、失败计零的端到端宏平均 precision 为 0.2079/0.5925/0.7680，recall 为 0.1587/0.5299/0.6946（顺序始终为 base/full128/new）。precision 和 recall 同时提升，不能解释为只靠少报对象来提高精度。

在共同完成的 base/new 95 世界，precision 为 0.2801→0.7556，recall 为 0.2138→0.6940；full128/new 123 世界为 0.6165→0.7674 与 0.5514→0.6946。此处 precision/recall 与主指标一样，同时要求类别正确和距离不超过 0.75 米，不是纯分类精度或纯检出率。

独立重算不同定位门槛的端到端 F1：

- 0.25 米：0.0474 / 0.1922 / 0.3297。
- 0.50 米：0.1121 / 0.4257 / 0.6289。
- 0.75 米：0.1771 / 0.5546 / 0.7248。
- 1.00 米：0.2353 / 0.6308 / 0.7659。
- 1.50 米：0.3201 / 0.6962 / 0.7987。

new 的收益在严格阈值下仍保留，但 0.25 米 F1 仅为 0.3297，定位远未解决。原评分器的空间关系 pair-F1 为 0.0486/0.2809/0.5015；该指标依赖对象先匹配成功，因此不能当作独立于检出/定位的关系推理测验。

另计算“忽略坐标、仅匹配每类数量”的宽松上界：F1 = 2×Σ类别 min(预测数量, GT数量)/(预测总数+GT总数)，失败仍计零。全部世界为 0.5497/0.7756/0.8598。在共同完成的 base/new 集合，上界为 0.7407→0.8645，而真实 F1 为 0.2386→0.7198；reader 共同完成集合的上界为 0.7713→0.8314，真实 F1 为 0.2661→0.6602。模式与实例对应/定位质量改善相符，但上界允许同类对象错认和碰巧数量正确，不能把两指标的差当成“定位贡献”。

对两模型均在 0.75 米内匹配到的同一 GT 对象，端到端 base/new 的 109 对对象来自 58 世界，平均误差 0.4222→0.2811 米；full128/new 的 368 对来自 117 世界，0.3396→0.2884 米；reader 的 133 对来自 65 世界，0.3754→0.3004 米。这些是截断且经过选择的对象集合，仅作描述，不把对象当独立统计样本。

## 新配方相对 full128 的收益及退化

new 相对 full128 的全部世界平均 F1 提高 0.1703；完成率由 96.09% 到 100%。128 个父世界中有 93 个提高、14 个持平、21 个下降。最大退化例 `w202609208` 为 1.0000→0.3333，不能用平均收益掩盖。

普通 96 世界的差为 +0.1910，物理遮挡 32 世界为 +0.1082。在普通世界八个家族（每家族 12 个）中，均值差均为正：open_sparse +0.0471、scale_rotation +0.1612、clustered +0.1640、perimeter +0.1776、elongated +0.2072、occlusion +0.2331、distributed +0.2650、repeated +0.2725。小样本家族均值不是八项独立确认结论，不能据此断言所有家族稳定提升。普通家族名为 occlusion 的 12 世界与经过物理验证的 32 世界始终分开统计。

new 在全部 128 世界相对 base 为 121 胜、2 平、5 负。new 仍有 3 个完成但 F1=0 的端到端世界；full128 有 1 个，base 有 30 个。完成不等于地图正确。

full838 相对 full128 同时改变数据规模、构成/质量和训练更新数，现有实验只能确认这套配方的净变化，不能单独识别纯数据量收益。

## 固定公共观察 reader 的证据

128 对首次 reader 请求的哈希一致，每个世界都是固定 16 帧原地扫描。base/new 完成数为 101/128，全部世界 F1 为 0.2100→0.6434。共同完成子集仍有 +0.3941 的差，说明改进不限于端到端选择了更多或不同观察；在同一初始公共传感证据下，reader 整体策略及输出能力也改善。

这并非纯视觉编码器能力测验：后续投影查询、工具反馈和答案组织均可不同。没有 reader/full128 评测，不应补出这一格。new 的 e2e F1 比 reader 高 0.0815，只是不同观察/策略条件的描述性差异；不能称其为主动探索的贡献，也不能用 e2e-new/base 差减去 reader-new/base 差作机制分解。

## 物理遮挡与观察—命中的关系

32 个物理遮挡世界中，base/full128/new 的目标被记录观察到数为 12/13/17，匹配数为 0/6/11。new 的完整四格为：观察到且匹配 10、观察到但未匹配 7、未记录观察到却匹配 1、未观察到且未匹配 14。于是 11 个匹配不能全部解读为成功发现隐藏物体；`w202619226` 是“未记录观察到却匹配”的实例，可能涉及先验/碰巧通过类别与距离阈值，当前数据不能判定原因。

reader 中所有 32 个隐藏目标都没有被记录观察到，也均未匹配。固定扫描不提供这一目标的视觉证据，所以 reader 的总体提升不能证明解决了物理遮挡恢复。

## 动作、调用和预算

全部端到端世界的平均帧数为 9.21/12.23/15.38；用满 16 帧的世界数为 3/6/78。实际归档调用总数为 987/1025/1309，平均为 7.71/8.01/10.23；采集/读出调用分别为 569+418、621+404、819+490。原 `status.calls` 不含响应截断等失败调用，因此这里用 `calls/*/meta.json` 计数，不能混用。

4 次读出预算用满的世界数为 81/29/106。new 全部成功完成，同时更常消耗接近上限的帧和调用；其收益不是相同实耗预算下的比较。每个端到端世界的平均 prompt token 为 30,134/44,884/69,628，completion token 为 2,430/1,638/2,384。token 只能作为记录的服务用量，不能据此推导同硬件时延或费用；base 截断调用也计入。

new 的额外帧主要不是大量增加平移步数：每世界含非零平移请求的实际回执数为 5.61/3.47/3.83，纯旋转回执数由各模型动作日志另列。公共回执可确认的累计平移路程下界为 2.36/1.90/2.19 米，加上 partial 的请求距离后的上界为 2.78/2.43/2.68 米；partial 的实际路程未知。这是路径长度范围，不是净位移。blocked/partial 后未执行的批次动作不计入。

终止和格式行为改善明显：new 有 128 次最终 finish 且均通过，base 端到端有 100 次 map.frame 错误拒绝和 102 次 JSON 提取拒绝。**但 new 的工具错误没有消失**：端到端有 63/128 世界出现明确工具拒绝，86 次投影请求超过 24 点；reader 有 96/128 世界出现明确拒绝，150 次同类超点数请求。另有逐点投影错误，使 new 端到端 104/362 次、reader 155/377 次 project_ground 操作被日志标为不可训练。该标记包含逐点错误，不能与整次调用失败等同；明确拒绝和该标记分别输出。

逐次解析实际工具回执后，project_ground 的“请求数 / 整批拒绝 / 返回含点错误 / 所有点未报错”为：端到端 base 100/0/14/86，full128 276/19/8/249，new 362/86/18/258；reader base 110/0/23/87，new 377/150/5/222。new 相对 full128 的全部点未报错调用只从 249 增到 258，整批拒绝从 19 增到 86，不能把请求次数增加称为更遵守工具协议。端到端工具返回未报错的点数为 518/3944/5373；reader 为 623/4791。**未报错只表示工具规则允许计算，不保证模型选到了真实地面像素、对应正确对象或对象中心。**

## 方法、复算与审阅

运行以下命令可在本目录重建 JSON，依赖 Python 与 numpy（不需要 scipy）：

```sh
python3 outputs/sft_followup_20260921/quant/recompute.py
```

脚本也接受 `--workspace /path/to/workspace`；所有写入仍限定在脚本所在目录。它读取 640 个 status、575 个 prediction、640 个 phases、4254 个调用元数据、128 个 GT 及原分析/摘要。全部 6243 个输入文件列在 `input_hashes.json`。

1. 与原封存分析逐一核对 640 个 status 的 SHA256，核对全部均值和原父世界摘要。
2. 独立重算 575 份完成预测在 0.75/0.25 米的 1150 个对象分数，全部与原分数一致。用类别/距离门控二分图最大匹配重算匹配数量；原 Hungarian 评分器在这些有限阈值下优先最大化匹配数，两者 F1 等价。位置误差沿用原 Hungarian 匹配，不使用另选的 DFS 匹配。
3. 逐次核对 4254 个归档调用与状态中的请求/token总数；均只有 attempt 0。对所有回执去重，并核对每个世界记录帧数。
4. reader 的 128 对初始请求哈希一致。动作 JSON 提取规则复现封存 `flash_client.parse_json`，不把模型额外包装文本自动算成格式错误。
5. 新增区间均为 20,000 次父世界配对 bootstrap，`statistical_resampling_seed=20260920`；这是固定统计随机数，不是新增训练 seed，也未新增训练。按普通/物理遮挡分层，共同成功子集保留其自身分层占比。原主分析的 50,000 次区间保持原样。新家族/子集分析未作多重性调整。当前探索脚本在发布前将统计随机数统一为 20260920，未改变原协议或已封存分析。

`quantitative_analysis.json` 保存汇总、配对比较、分层/家族、所选案例及解释边界；`per_world_quantitative.json` 保存全部 640 行及动作/工具统计，可逐世界审阅。`reproduction_manifest.json` 保存代码、输出哈希和运行版本。

如需进一步识别机制，后续实验可在封存新协议后比较同一观察轨迹交叉 replay 给各 reader、匹配实际帧/调用预算，以及无图/打乱图/扰动坐标等负对照。这些实验本次均未执行，当前数据不能排除同分布资产或几何先验的作用，也不能证明跨训练 seed、未见资产或真实世界泛化。
