# 微调后行动轨迹独立复核

样本：最新 attempt03 / 419-step checkpoint，128 个 E2E 配对场景。本文读取原始压缩 pair 与 call 导出，不使用 reader 固定轨迹替代实际行动。另报双方 COMPLETE 的 95 个场景，避免把 base 33 个失败终止直接混同于主动少观察；该子集本身存在完成条件的选择偏差。全部结果是记录上的观察性比较，不证明某个动作导致得分变化。

## 最有价值的新增发现

1. **更多帧主要来自旋转，并非更远探索。** 全128例，平均实际路径 base 2.576m → SFT 2.441m，独立位置5.55→3.79，移动步5.23→3.58；帧数9.21→15.38，原地旋转2.90→10.76。双方完成的95例，实际路径2.623m→2.669m，独立位置5.49→3.83。故“观察更多”不能直接解释为“走得更远/覆盖更大地面面积”。

2. **原地转向确实带来大量新视图，同时后段存在明显重复。** 全128例，产生此前未出现图像的原地旋转均值2.24→7.19；不同图像8.05→10.96。因此不能把原地旋转全部算作浪费。但总体帧口径（micro）完全重复图像为149/1179=12.64%→565/1968=28.71%；按案例先求比例再平均（macro）为12.09%→28.36%。95个共同完成案例的micro比例为113/872=12.96%→422/1459=28.92%，macro为12.43%→28.49%，产生新图的原地旋转2.24→7.09。全部3603张本地PNG均逐字节计算SHA256并与文件名一致，重复判定不是视觉相似猜测。

3. **接近一半 SFT 场景以长串旧照片结束。** 62/128例最后至少4帧均与此前图像同字节（base2/128）；16/128例最后至少8帧重复（base0）。共同完成95例仍为46/95 vs1/95（至少4帧）。这些是“没有新增图像字节”的直接证据，不代表重复上下文绝无计算作用；若要确认对最终结果的影响，必须做截断/去重读图消融。

4. **8例走9m却只到4个位置：成功分数掩盖行动重复。** 场景 w202609214、236、246、248、280、285、292、w202619209 在初始三次+90°扫描后，连续12步都为−90°、0.75m。实际是边长0.75m的方形绕3圈，16帧仅7张不同图，9帧重复；其中w202609246、248、280、292仍然F1=1。w202609214 的 acquire_05_0 声称探索了“a 3x3 grid of camera positions”，而轨迹只含4个位置，frames4/8/12/16完全同图。不能用模型的finalize理由代替轨迹事实。

5. **碰撞次数减少，按移动机会计的碰撞率没有减少。** partial+blocked次数147→116，但发出的非零移动请求718→490，所以碰撞/移动请求20.47%→23.67%；95个共同完成例为95/528=17.99%→75/385=19.48%。SFT更多旋转、少移动，因此“碰撞总数下降”不是更安全移动的证据。此分母按实际帧receipt而非被碰撞提前截断的整批计划计算。

6. **碰撞后的平移恢复值得单独改进。** 以“第一次partial/blocked之后仍至少有4个观察帧”为入选条件，base42例中6例随后完全没有实际平移；SFT66例中52例如此。同时满足双方条件的26个配对场景里，base1/26 vs SFT19/26后续不再平移。该条件选出了特定行为子集，不能把它解释成碰撞的因果效应；但它给出了可逐例检查的策略差异。

## 具体证据案例

- **旋转有用且零重复：w202609277。** 双方完成，base走7.00m、15帧、13张不同图；SFT走3.70m、14帧且14张全不同，8次原地旋转全部产生新图，F1从0→1。SFT frames2–4为原点扫描，之后移动与新位置扫描组合；acquire_04_0终止采集，readout_02_0输出5个对象。此例支持“移动更少也能取得互补视图”，不是该策略普遍优越的因果证明。

- **覆盖相同却退化：w202609205。** 双方COMPLETE、seen均5/5；base7帧/7不同图/7位置/2.55m，SFT16帧/9不同图/3位置/1.50m，F1从0.25→0。SFT第4帧记录的seen已含全部5个GT，第10帧后余下6帧全部旧图，frames6/8/12/16同hash，frames7/11/15同hash。acquire_05_0宣称4种对象已经全部识别，但GT有5种且最终地图缺chair；readout_03_0中的floor_lamp坐标(0,0)、table(0,1.5)。此例把“环境seen覆盖”“模型识别”“定位正确”三个概念明确分开。

- **退化且碰撞后不换位置：w202619203。** base路径5.50m、16帧15张不同图、seen4/6，F1=0.2；SFT仅实际0.65m、14帧8张不同图、seen3/6，F1=0。SFT第5帧请求0.75m得到partial，后续只在同一位置转向，第9–14帧均重复先前图像。acquire_05_0仍宣称所有对象已被识别定位，最终readout_03_0只输出两张bookshelf实例。

- **“分数提升”也可能掩盖探索失败：w202619223。** base最终FAILED/F1=0，但曾实际走2.65m且seen7/7；SFT完成/F1=0.222，仅走0.20m、15帧7张不同图、seen2/7。SFT第5帧partial，第9帧blocked，最终7帧全是重复图；acquire_06_0仍说“only objects present are a bookshelf and a book”。这不说明base更好，但说明完成率和探索质量应分开报告。

- **seen不是理解或召回上限：w202619226。** SFT seen只有4/5（缺o2 plant），最终仍匹配5/5、F1=1。readout_00_0主动对frame8的plant_base点请求投影，readout_03_0预测plant并引用frames8/10/14。因此不能把导出的seen计数当作模型一定看见/没看见、理解/不理解的结论；需回查环境seen阈值定义后再解释该覆盖指标。

## 与分数、调用成本的关系

按seen_fraction变化，全128例：更高覆盖31例中30提升、1持平、0退化；相同覆盖89例中84提升、1持平、4退化；更低覆盖8例中7提升、1退化。当前E2E数据不存在“覆盖更高而分数更差”的案例，不应为了叙事虚构；w202609205是覆盖相同而明显退化的反例。5个退化案例的SFT路径都更短，但大量提升案例也更短，不能由此认定短路径导致退化。

双方seen最终均为全部GT的76例中，base首次seen全部平均第4.70帧、SFT第3.71帧；此后仍继续4.32帧→11.57帧。seen不等于识别/定位充分，因此这只说明“新增对象计数”很早饱和，不能直接用它作为停止条件。

全128例平均调用7.71→10.23，日志累计调用秒数43.59→65.29；共同完成95例调用8.02→10.13，秒数37.23→65.16。日志时间是这次部署的观测成本，不是控制硬件/并发后的模型速度基准。

## 建议做的针对性实验

- 增加同字节图像新颖度、末尾连续重复长度、独立位置数作为行为指标，和F1一起报告。
- 针对方形重复与原地重复加入序列去重/换位提示；对比相同预算下是否增加新视图、是否保持F1。不能只因当前分数高就认为重复没有代价。
- 在partial/blocked后优先检查可行的侧向或回退路径，将“尝试恢复平移”纳入训练案例；用匹配场景的干预评估，不以当前相关统计宣称效果。
- 对末尾4–9帧重复案例做“保留完整轨迹、读图输入去重”和“提前结束采集”两种不同消融，区分减少输入重复与改变决策时机的作用。

## 数据与复现

输出JSON的compact字段是面向展示的精简统计；rows保留全部128配对指标，selected_cases保留以上6例帧、请求receipt与精确call答案。输入全部来自 work/site-edit/client/sft-data/pairs/*-e2e.json.gz 与对应calls。实际路径使用连续xy欧氏位移相加，全部256运行都与distance末值减初值在1e−7m内一致；独立位置按5位小数去重，heading取模360。

依次运行 work/analysis/behavior/analyze.py、refine.py、collision.py 可重新生成JSON。首轮127/128固定三次90°扫描为对旧站既有发现的独立复核，本文不将其视为新发现。
